## 1. Correctness defects

### 1.1 Layout silently dropped Edge/Node fields — C4 relationships rendered wrong

**The most consequential finding, and it was reaching real output.**

`layout/layered.py::_route_edges` and `layout/sequence.py` rebuilt every `Edge`
(and, in sequence, every `Node`) field-by-field from a hand-picked list. Every
field outside that list silently reset to its dataclass default on the way out
of layout.

What that cost in practice: `object_attributes` was dropped, and that is exactly
what makes the generator wrap a cell in a `<UserObject>` and inherit the
palette's label template. So **every C4 `Rel` lost its wrapper** and fell back to
a bare `value=` label — losing the `c4Type`/`c4Description`/`c4Technology`
attributes and the shape-library rendering the generator's own docstring
promises ("so a C4 Rel renders like its shape-library entry instead of a bare
label"). Sequence layout additionally dropped `variant`, `text_parts`,
`element_name` and `child_cells`.

Two things made this invisible:

- `engine/validate.py::_iter_edge_cells` exists specifically to find edges
  inside `<UserObject>` wrappers — it was handling a case that no longer
  occurred.
- The end-to-end test `test_edge_endpoints_resolve_to_vertices` scanned only
  direct `mxCell` children, so it silently checked *zero* C4 edges.

`layout/palette.py` had already hit this exact defect and fixed it with
`dataclasses.replace`, with a comment explaining why — the lesson just never
propagated to the other two layouts.

**Fix:** all three layouts now use `replace()`. Verified against real output:
`docs/architecture/c4_architecture.mdg` now emits 52 `<UserObject
c4Type="Relationship" … placeholders="1" label="…%c4Description%…">` wrappers
where it previously emitted none.

**Guarded by:** `test_layered_routing_preserves_non_geometry_fields`,
`test_sequence_placement_preserves_non_geometry_fields`,
`test_c4_relationships_render_with_the_palette_label_template`, and the
now-non-vacuous `test_edge_endpoints_resolve_to_vertices` (which asserts it
found edges at all, and uses the same wrapper-aware helper as the validator).

### 1.2 An unknown `use <lib>` silently rendered as C4

`engine/convert.py:75` fell back to `"c4"` whenever the `use` statement named a
library that does not exist. A typo (`use bpnm2`) laid the whole page out with
the wrong notation's layout config, shape scaling and rank exclusions, and
exited 0 with no diagnostic. This directly contradicts the principle the
neighbouring `_normalize_direction` states in its own docstring: *"An unknown
value is a loud error, not a silent fallback."*

**Fix:** unknown library now raises with the list of valid ones. A page with no
`use` line at all still defaults to c4 — that is legitimate and stays supported.

**Guarded by:** `test_unknown_use_statement_is_rejected`,
`test_page_without_use_statement_defaults_to_c4`.

### 1.3 Hyphenated node ids worked in C4 and nowhere else

An unquoted id like `my-node-1` parses as a chain of subtraction nodes. The
native C4 parser has always recovered those (`literal_or_name`, whose docstring
says so explicitly), but the shared passthrough builders used a narrower
extractor. So `erd.EntityRect(my-node-1, "Label")` failed with a confusing
*"first argument must be a node id"* while the identical construct in c4 worked.

This matters beyond aesthetics: the reverse-derivation POC seeds `node_id`s from
draw.io cell ids, which routinely contain hyphens.

**Fix:** new `_extract_arg_id` (`dsl_engine.py:1221`) applies the same recovery
for node ids and edge source/target across every notation. Label and title
extraction keep the stricter behaviour.

**Guarded by:** `test_passthrough_accepts_unquoted_hyphenated_ids`,
`test_passthrough_edge_accepts_unquoted_hyphenated_endpoints`.

### 1.4 Two representations of containment that disagreed

`Node.contains` is a first-class contract field. The generator keys its
container detection off it (`n.contains or …`). The container layout instead
read containment from `extra["contains"]` and never looked at the field.

Neither is populated by any parser today (they all use `parent_id`), which is
why nothing broke — but any caller setting the declared field would have got a
node whose edges were routed *as a container's* while its children were never
laid out inside it. A split-brain waiting to happen, invisible to the dead-code
analysis because that tool inspects `def`/`class`, not dataclass fields.

**Fix:** `_contains_ids` (`_container_layout.py:96`) now reads both forms, and
`Node.contains` carries a comment explaining its relationship to `parent_id`.

**Guarded by:** `test_layered_lays_out_children_declared_by_contains`
(parametrised over both forms).

## 2. Duplication and dead surface

- **Three copies of the style-token loop** in `generator.py`
  (`_style_overrides`, `_overrides_to_style`, `_style_overrides_for_edge`) —
  which had already drifted apart on the empty-input case. Collapsed into
  `_style_tokens` + `_tokens_to_style` (`generator.py:307`).
- **`registry.shapes_by_function` re-implemented `index_shapes_by_function`**,
  whose docstring claims to be *"the single source for the `{function:
  [entries]}` transformation shared by the registry, the DSL engine, the layout
  size resolver, and the generator's StyleProvider"*. It now actually is.
- **`_is_none_literal` duplicated** in `c4/__init__.py` and `dsl_engine.py` —
  promoted to `is_none_literal` in the shared engine.
- **Nine dead constants removed** from `contracts/`: `DEFAULT_LANE_MARGIN_X/Y`,
  `DEFAULT_COLUMN_GAP`, `DEFAULT_PAGE_MARGIN`, `MIN_CONTAINER_WIDTH/HEIGHT`,
  `NARROW_CHAR_WIDTH`, `WIDE_CHAR_WIDTH`, `RELATIVE_CHAR_WIDTH`. The char-width
  trio was worse than unused — it was a second, *misnamed* copy of the real
  values in `_container_layout.py` (6.5 is the average character width, not the
  narrow one, which is 4.0). Those now live in one place, next to the estimator
  that owns them, with the previously-inline 4.0 named.
- **`_DEFAULT_BOUNDARY_PADDING`** in `_container_layout.py` was dead, and was
  the module's only reason to import from `contracts` at all.
- Stale docstring in `contracts/models.py` advertising `to_dict()`/`from_dict()`
  that do not exist — replaced with a note telling future maintainers to use
  `dataclasses.replace` rather than reconstructing field-by-field, since that
  habit caused §1.1 twice.
- Duplicated comment line and five stray blank lines in `dsl_engine.py`.

## 3. Performance

- `generator.generate` built `container_ids` with a nested scan
  (`any(c.parent_id == n.id for c in document.nodes)` inside a comprehension
  over all nodes) — O(n²). Now one pass.
- `_longest_path_ranks` and `_topological_ranks` used `list.pop(0)` on a BFS
  frontier — O(n) per step, making ranking quadratic. Both use `deque`.
- Three dead parameters removed (`_order_layers`, `_assign_positions`,
  `_layer_graph`'s returned `node_by_id`) and a redundant dict round-trip in
  `_layers_from_ranks`. `_coerce_variant` was computed twice per edge; now once,
  which also guarantees the style and its label template cannot disagree.

## 4. Gate improvements

The point of these is that the *gate* catches the next instance, not a reviewer.

- **`tests/test_container_view.py` now rejects stale allowlist entries.** The
  symbol allowlist only ever *permitted*, so an entry for a symbol a module
  stopped importing sat there passing forever. That is precisely how
  `_container_layout.py` came to declare three constants it never imported, and
  how those constants stayed alive in `contracts` with no consumer at all.
- **ruff gains `W`, `UP`, `RUF`.** These caught a stale `__all__` ordering and
  an outdated `TypeAlias`.
- **`ARG` and `SIM`/`PERF` were considered and rejected**, with the reasons
  recorded in `pyproject.toml` so they are not re-litigated. `ARG` is the rule
  that would have flagged the dead parameters in §3, but `BaseLayout.apply` and
  the parser Protocols (`IsEdge`, `NodeBuilder`) genuinely require conforming
  signatures, so every implementation legitimately ignores some argument and
  ruff cannot tell those from dead weight. `SIM`/`PERF` produced 17 findings,
  all readability washes in scripts and tests with no defect behind them —
  enabling a rule and then blanket-ignoring it is worse than not enabling it.
- **`style_fingerprint` now passes `usedforsecurity=False`** to SHA-1. It is a
  content hash for change detection; the flag states that and keeps it working
  on a FIPS-restricted build, where an unflagged SHA-1 raises. Digests are
  unchanged, so committed registry fingerprints are unaffected.
- Two `# noqa` comments carrying real rationale for broad `except` clauses were
  stripped by ruff's autofix; the rationale was restored as plain comments.

The architecture model behaved exactly as advertised throughout: every import
change I made was caught by `make model-check` and required updating
`c4_architecture.mdg` / the code-view lockfile / the relationship snapshot
before the gate would go green again. That machinery earns its keep.

## 6. Follow-up — edge routing is now opt-in (`6f66ade`)

Requested after the review: process mode's elbows are right, but no other
layout should emit waypoints by default.

`LayeredLayout` gained `route_edges`, **off by default**. An ordinary ranked
diagram now emits no edge geometry and draw.io draws its own paths.
`ProcessLayout` constructs `LayeredLayout(route_edges=True)`.

Two decisions worth knowing:

- **Anchors go with the waypoints, not separately.** `_route_one_edge` picks
  both together — an arc around an obstruction only makes sense with the
  anchors aiming into it, and a fan-out branch's forced exit side is chosen to
  pair with its elbow. Emitting anchors without the path they were computed for
  would pin edges to ports for a route that is no longer drawn. Anchors an
  author set explicitly, or that come back from an existing `.drawio` via the
  geometry overlay, are applied *after* layout in `engine/convert.py` and are
  untouched. If you'd rather keep computed anchors and drop only the waypoints,
  it's a one-line split of the same flag.
- **Sequence and palette were left alone.** Their waypoints are not heuristic
  routing: sequence's *are* the message lines, and palette's are a verbatim
  reproduction of the pre-baked palette file. Stripping either breaks the mode.

Verified on real output — `c4_architecture.mdg`: 0 waypoints, 0 anchors, 52 C4
`Rel` `<UserObject>` wrappers intact. `tests/output/test_bpmn_process_swimlanes.mdg`:
12 elbow arrays and 4 anchors kept. All seven coverage sheets still convert.

**Latent defect found in the same code path and fixed:**
`_restore_reversed_edges` ran *after* routing. Routing copies each edge, so the
restore only ever un-swapped the originals — which are then discarded — and the
emitted copy of a back edge kept its ranking-time (reversed) orientation, with
an id (`b->a`) that disagreed with its own source/target. It stayed invisible
because a reversed edge is also marked `hidden`, so draw.io never drew it. The
restore now runs before routing. Guarded by
`test_layered_restores_back_edge_orientation_on_the_emitted_edge`.

Gate after this change: 451 tests in `tests/`, `make check` green.
